1. アプリ概要

「無理なく働き続けられているか」「疲労やストレスが蓄積していないか」を、毎日の短い記録から振り返ることを目的とする。

毎日3〜5分入力の目安時間。負担を増やさない
1〜5段階全評価項目を同じ方向で統一
7日・30日短期と中期の傾向を確認
セルフチェック医療的診断ではなく、自己理解と相談の補助

想定利用シーン

  • 勤務終了後や就寝前に、その日の状態を簡単に記録する。
  • 睡眠・疲労・ストレス・業務量の変化を時系列で確認する。
  • 週単位で振り返り、負荷の調整や家族・上司・医療機関への相談に役立てる。

2. 基本設計方針

デザインコンセプト：Soft / Calm

  • 淡いグリーン、ベージュ、ブルーなど低彩度のパステルカラー。
  • 角丸のカード、余白を広く取ったレイアウト、柔らかい文字表現。
  • 強い警告色や不安を煽る表現を避け、落ち着いて振り返れる画面にする。
  • スマートフォンで片手でも操作しやすいタップ領域を確保する。

評価値の統一ルール

すべての評価項目で「5＝良好、1＝不調」に統一する。
疲労・ストレスは「疲労の少なさ」「ストレスの少なさ」として尋ねるか、内部値を反転してグラフ上の方向を統一する。
値共通の目安
5とても良い・問題なく過ごせた
4概ね良い・少し気になる程度
3普通・やや負担を感じた
2あまり良くない・負担が大きい
1かなり悪い・強い不調を感じた
各項目の具体的な説明は、利用者が迷わないよう入力画面に短い補足を表示する。数値だけで健康状態を判定しない。

4. 毎日の記録仕様

入力負担を抑えるため、必須項目は最小限にし、自由記述や詳細項目は任意とする。所要時間は3〜5分を目安とする。

分類項目入力形式必須案
睡眠睡眠時間時間・分任意
睡眠睡眠の質1〜5推奨
身体身体的な調子／疲労の少なさ1〜5推奨
精神精神的な余裕／疲労の少なさ1〜5推奨
気分今日の気分1〜5推奨
ストレスストレスの少なさ1〜5推奨
仕事業務量少ない／適切／多い推奨
仕事負担感・無理をした感覚選択式または1〜5任意
仕事集中しやすさ1〜5任意
支援困りごと・相談したいこと自由記述任意
生活休息・家庭での時間選択式／自由記述任意
振り返り今日できたこと自由記述任意
振り返り気になったこと・明日気をつけたいこと自由記述任意

記録時の操作要件

  • 選択式の評価はタップ数を少なくし、選択状態を視覚的に明確にする。
  • 入力途中の一時保存、保存済み記録の編集を可能にする。
  • 未入力項目があっても、必須項目を満たせば保存できる。
  • 同じ日付の記録は原則1件とし、後から編集できる。
  • 体調が悪い日でも記録を強制しない。未記録を失敗として扱わない。

5. 分析機能仕様

5.1 コンディション推移グラフ

  • 総合・睡眠・疲労・ストレスなど複数系列を1つの折れ線グラフに重ねて表示する。
  • 系列ごとに表示／非表示を切り替えられる。
  • 表示期間は7日間／30日間を切り替えられる。
  • 縦軸は1〜5で固定し、5が良好、1が不調となるよう統一する。
  • 日付または期間単位の値を確認できる。未記録日は欠損として扱い、ゼロで補完しない。
  • 系列の色と凡例を固定し、画面間で同じ色を使う。

5.2 分析カード

分析項目表示内容目的
総合コンディション選択期間の平均・前期間との差全体の変化を把握
項目別平均睡眠・疲労・気分・ストレスの平均変化の大きい項目を把握
業務量との関係業務量区分ごとのコンディション平均仕事の負荷との関連を確認
睡眠と疲労両系列の時系列比較睡眠と翌日の疲労の変化を確認
休日の回復休日の前後で各項目を比較休息で回復できているかを確認
記録状況記録日数・記録率継続状況を確認

5.3 期間別振り返り

  • 7日間：直近の変化、急な落ち込み、連続した変化を確認。
  • 30日間：本人の通常時の水準、週ごとの変化、負荷との関連を確認。
  • 将来的には週次レポートとして、良かった点・気になる変化・次週に試すことを簡潔に提示する。
分析上の注意：相関が見られても因果関係を断定しない。記録件数が少ない場合は「データ不足」と表示し、無理に傾向を判定しない。

6. データ設計（実装時の基本案）

記録と分析を分離し、分析値は保存済みの記録から都度算出できる構成を基本とする。

データ主なフィールド案説明
DailyRecordid, record_date, created_at, updated_at日次記録の識別情報
Conditionsleep_quality, physical_condition, mental_condition, mood, stress_level1〜5の評価値。内部表現は5が良好
Workloadworkload_level, concentration, burden, overexertion業務量・集中・負担感
LifeNoterest_note, family_note, achievement_note, concern_note, tomorrow_note任意の自由記述
AppSettingsreminder_time, enabled_metrics, theme, export_preferences通知・表示・ユーザー設定

保存・データ管理要件

  • 日付を基準に記録を検索し、編集・削除できる。
  • データのバックアップ／エクスポート手段を用意する。
  • 個人の健康・勤務に関する情報を扱うため、アクセス制御と通信・保存時の保護を設計する。
  • 分析画面は実データのみを使用し、サンプルデータは明確に区別する。
  • データ保存先、同期方式、認証方式は実装前に決定する。

7. 変化への気づき支援

将来的に、次のような変化を検出し、本人が振り返るきっかけを提示する。

検出候補表示例
精神的な余裕が数日続けて低下「ここ数日、精神的な余裕が下がっています。負担になっていることはありますか？」
睡眠の質が継続して低下「睡眠の質に変化が見られます。就寝前の過ごし方や休息を振り返ってみましょう。」
業務量が多く、ストレスも高い「業務量とストレスが重なっています。仕事の優先順位や相談先を確認してみましょう。」
休日後も回復が見られない「休息後も疲労が続いているようです。無理を続けず、必要に応じて周囲や専門家に相談しましょう。」
アラートは診断・予測を断定するものではない。本人の気づきと、休息・業務調整・相談を支援するための参考情報として扱う。

8. 実装ロードマップ

段階実装内容完了条件
Phase 1
記録基盤		記録フォーム、日付管理、保存・編集・削除、データモデル入力した内容が再起動後も保持され、履歴から確認できる

分析画面		7日／30日切替、複数系列グラフ、系列表示切替、平均値実際の記録データに基づくグラフが表示される

関連分析		業務量とストレス、睡眠と疲労、休日回復の比較データ件数を考慮し、根拠となる期間・件数を表示できる
Phase 4
振り返り支援		週次レポート、連続変化の検出、気づきメッセージ誤解を招かない表現で、本人が行動を考える材料を提示できる
Phase 5
運用改善		エクスポート、バックアップ、通知、アクセシビリティ改善日常的に安心して継続利用できる

9. 未決定事項・次に決めること

  1. 利用環境：スマートフォンのWebアプリ（PWA）として作るか、ネイティブアプリにするか。
  2. 保存先：端末内のみ、クラウド同期あり、または両方を選べる方式にするか。
  3. 認証：個人利用を前提に、ログインを設けるか。
  4. 必須項目：毎日の入力負担と分析上の有用性を見ながら確定する。
  5. 総合スコア：単純平均にするか、各項目の重み付けを行うか。初期版では単純平均または総合自己評価を優先し、算出方法を明示する。
  6. 通知：毎晩21時のチェック促進を利用するか、アプリ内通知と連携するか。
  7. 既存チェックシート：復職トライアルで使っていた項目を確認し、重複や不足を整理する。
